# 外部更新・自動更新・読書位置維持の検証

日付：2026年10月29日。macOS 27.0.1／Apple Silicon、Rust 1.95.0。
今回のゴールは、外部保存を自動反映し、同じセッション内で読書位置を可能な範囲で保つこと。
再起動後の復元を含むD05全体の完了ではない。

## 実装

- notify 8.2.1（MIT OR Apache-2.0）を採用し、Cargo.lockへ固定。
- 表示中の文書の親ディレクトリを非再帰で監視。対象ファイルの変更・置換に関係する通知だけを扱う。
- 200msの静穏待ち、最大1秒で連続通知をまとめる。定期ポーリング・ディレクトリの走査はしない。
- 読込エラーには80/160/320msの待ちを挟んで再試行。失敗しても最後の正常な本文を保持する。
- タブ切替時に旧監視を停止。背景タブは選択時に再確認する。アプリのフォーカス復帰と⌘R／Ctrl+Rでも再確認する。
- 監視世代と画面側のタブ・要求番号を照合し、古いタブの完了を現在の本文へ反映しない。
- 同じ表示HTMLならDOMを作り直さない。選択中・日本語IME変換中は最新の反映を待つ。
- 更新前の段落・出現順・近い見出し・画面内の位置を一時メモリで保持する。一致が曖昧なら近い位置へ戻し通知する。
- 自動更新で検索入力のフォーカスやメニューを操作しない。画像の寸法をHTMLへ含め、画像の読込で位置が動くのを抑える。

## 確認したこと

| 検証 | 結果 |
| --- | --- |
| Rustの既存7テスト | 成功 |
| 実OS通知の追加2テスト | 上書き、置換、連続保存、不正UTF-8からの復旧、監視切替・停止を確認 |
| 画面の更新試験 | 前方への段落追加後も同じ段落の画面内位置を維持（試験条件内で2px以内） |
| 反映の抑制 | 選択中は旧本文を保持し、選択終了後に反映することを確認 |
| 読込失敗 | エラー通知を出し、最後の本文を保持することを確認 |
| 古い結果 | 要求番号の古い更新結果を無視することを確認 |
| 段落消失 | 正確な復帰ができないことを通知する動作を確認 |
| macOS実アプリ | 外部ファイルの保存だけで新しい見出しが現れることをAXで確認 |
| Vim | /usr/bin/vimの非対話モードでbackupcopy=noの置換保存を行い、実アプリの自動反映を確認 |

画面試験はBrowserプラグインがないためPlaywright／Chromiumで実施。
Rustの実レンダラーから得た更新前後の文書で、画面側へ更新イベントを渡して検証した。
これとmacOS実アプリのOS通知からの反映確認を分けて扱う。

テストは独立した合成ファイルで行い、元のREADMEや利用者の文書を保存操作の対象にしていない。
試験用ファイルは一時領域へ残している。位置維持は全編集パターンの保証ではない。

## 制約と未検証

- Windowsの通知、置換保存、実アプリでの位置維持は未検証。
- VS CodeそのもののGUIを使った保存操作は未実施。通常の上書き・置換保存は合成操作で確認した。
- 実際の日本語IME操作、選択解除と保存の高速な競合、読み上げとの併用は未検証。
- 画像ファイルだけの変更は監視しない。文書の再読込時に読み直す。
- 親フォルダー自体の移動・削除、ネットワーク共有、通知を発生させないファイルシステムへの追随は保証しない。
- 保存途中でも有効なMarkdownとして読める内容の完成度までは判別しない。
- 再起動後のタブ・読書位置復元は未実装。消費電力や全OSでの軽量性は今回測定していない。

Rustfmt、Clippy、ビルド、markdownlintも再実行する。
依存監査のvulnerabilitiesは0件、warningsは既存と同じ5件。警告の除外設定は追加していない。
既存の旧ラボと配布アーカイブを保全し、push・公開・外部送付は行っていない。

## 再実行

```sh
rustup run 1.95.0 cargo test --manifest-path reader/Cargo.toml --locked
rustup run 1.95.0 cargo clippy --manifest-path reader/Cargo.toml --locked --all-targets -- -D warnings
rustup run 1.95.0 cargo run --manifest-path reader/Cargo.toml --locked -- README.md
```
