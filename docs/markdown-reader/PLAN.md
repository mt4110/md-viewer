# md-viewer 最小設計

状態：2026年10月29日。D01〜D03の基本実装とmacOSでの確認を実施。配布・Windows実機・性能測定の完了は未確認。
[README](../../README.md) は利用者向け、本書は実装の判断基準とする。

## 1. ゴールと対象

最終ゴールは、Markdownの表示方法を知らない非エンジニアが、AIや他人から受け取った文書を迷わず開いて読めること。
今回のゴールは、md-viewerの名前、Windows/macOSの導入、タブと復元、読みやすさ、軽量性の検証方法を定めること。
エディタ設定やCLI、Markdown構文、lint修正を利用者の前提にしない。

主な利用者は、AIが生成したメモ・説明書、同僚から受け取った手順書・資料を確認する人。
職種をエンジニアに限定せず、読むために別のアプリや拡張機能を設定する必要を感じていない人を対象にする。
導入後の初回操作は「ファイルを開く」またはドロップ。サンプルや登録手続きを必須にしない。

## 2. 初期版の体験

1. セットアップし、アプリを起動する。
2. 受け取ったファイルをドロップする。記号の羅列ではなく整形された文書を表示する。
3. 文字を大きくする。目次・検索で目的の箇所へ移動する。
4. 別のファイルを開くと新しいタブに入り、元の文書へ切り替えられる。
5. 閉じて起動し直すとタブが戻り、選んだタブの読書位置から再開できる。

初回の空画面は「ファイルを開く」、ドロップの説明、最近の文書を置く。
アカウント、ライブラリ登録、フォルダー移動、開発用環境は要求しない。
更新中・空文書・読込失敗・参照先の欠落は、日本語で状態と次の操作を示す。

日本語を既定とし、表示設定とネイティブメニューからEnglishへ切替可能にする。文書本文は翻訳しない。
文字色・背景色の個別指定、配色プリセット、初期値への復帰を提供し、言語と表示設定だけを端末内へ保存する。
低コントラストの配色を選んだ場合は設定内で控えめに案内する。OSのファイルダイアログはOSの言語に従う。

## 3. 表示と操作

一つのウィンドウにタブ列と一つの本文を置く。本文の目次は開閉でき、狭い画面では重ねて表示する。
操作はメニューのトグルへまとめ、既定で閉じる。検索欄も既定で隠し、⌘F／Ctrl+Fかメニューから開く。
Escで検索欄とメニューを閉じる。タブ列は複数文書が開いている場合だけ表示する。
見出し・本文・ナビゲーションの意味をHTMLに持たせ、選択・コピーはOSの通常動作を使う。

| 項目 | 初期仕様 |
| --- | --- |
| 日本語本文 | 初期案は18px、行高1.8、最大幅42em。実文書と利用者確認で調整 |
| 表・コード | その領域だけ横スクロール。本文全体を横にはみ出させない |
| 文字サイズ | 常に見つけられる拡大・縮小と既定値へ戻す操作 |
| 表示設定 | 読み幅、OS連動／明るい／暗い。設定を保存 |
| 検索 | 「この文書」「開いているタブ」を切替。本文・表・コードを対象。件数、前後移動、該当なし。IME変換中は確定しない |
| 目次 | 階層、現在の節、移動。閉じたら本文へフォーカスを戻す |
| リンク | ローカルの関連Markdownは別タブで開く。同じ文書が開いていれば既存タブへ移動 |
| コピー | 原稿を変更せず選択文字列をコピー。チェックボックスも閲覧専用 |

macOSはCmd、WindowsはCtrlを基本とし、Oで開く、Fで検索、+/-で文字サイズ、0で既定値、Wでタブを閉じる。
Windowsの戻る／進むはAlt+Left／Right、macOSはCmd+[／]。タブの切替はCtrl+Tab／Ctrl+Shift+Tab。
検索の次／前はWindowsでF3／Shift+F3、macOSでCmd+G／Shift+Cmd+G。Escで検索・目次を閉じる。
キーボード操作、200%表示、Windowsの拡大率、VoiceOver／Narratorを各OSの実機で確認する。

文書内検索を既定とし、タブ横断検索は「開いているタブ」へ範囲を切り替える設計とする。
横断結果は文書名と該当箇所を表示し、選択でそのタブへ移動する。未開封ファイルやフォルダーの走査は含めない。
横断検索も実装した。検索語・範囲は検索UI全体で共有し、永続化しない。Enter／Shift+Enterで次／前へ移動する。
結果は先頭200件まで。クリックで該当タブの一致へ移動し、一覧を畳む。「検索結果」で再表示する。
復元した未読込タブはRustで本文だけ読み、画像を読み込まない。本文の検索キャッシュはメモリ内8MiBまで。
読み込めないタブは件数を通知し、ほかの結果を利用できる。変更済みの一致へ誤って移動しないよう選択時に本文を照合する。
背景の既読込タブは表示用の内容、未読込タブは最初に検索した時点の内容を使う。背景での全ファイル監視は行わない。
画像の代替文・画像エラー・生成した情報見出しは対象外。別の段落をまたぐ語句・正規表現には対応しない。

### 文書内の戻る・進む

目次・同一文書の見出しリンク・検索一致への移動について、直前の読書位置をタブごとに記録する。
通常のスクロール、タブ切替、自動更新は履歴を増やさない。別文書のリンクは従来どおり別タブで開く。
「戻る」は別タブへ戻る操作ではない。検索で別タブへ移動した場合は、移動先タブ内の直前位置を記録する。

メニュー内に「戻る／進む」を置き、履歴がなければ無効にする。JA／ENに対応する。
macOSの⌘[／⌘]、WindowsのAlt+←／→に対応する。入力欄・選択欄・IME変換中のキー操作は奪わない。
戻った後で新しい場所へ移動したら進む履歴を破棄する。同じ位置への再移動や見つからない見出しは履歴を増やさない。

位置は既存の段落ハッシュ・同文出現順・見出し・本文表示領域からの相対オフセットを利用する。
本文が外部更新されたら同じ段落を優先し、失われていれば近い位置に戻って通知する。古い本文の版へ戻す機能ではない。
目次を開く前の位置を保持し、選択中のスクロールを移動元と取り違えない。
遅延した見出し移動はアクティブタブと切替世代を確認してから適用する。

履歴の責務はDOM上の読書位置を扱うUI側に置き、Rustで別の履歴を二重管理しない。依存追加は不要。
一方向100件までの軽量なアンカーをメモリに保持する。本文コピーや版、ファイルの走査は追加しない。
閉じたタブの履歴は破棄する。再起動では既存の最終読書位置だけを復元し、この移動履歴は永続化しない。

## 4. タブ・復元・更新

| 操作 | 決める振る舞い |
| --- | --- |
| 複数ファイルを開く | ファイルごとにタブ。開いた順を維持し、最後に選んだものを表示 |
| 同じファイルを開く | 正規化した対象が既存タブにあれば、そのタブへ移動。文字列を小文字化するだけで同一判定しない |
| タブを切り替える | 文書内位置、戻る・進むの履歴をタブ単位で保持。検索語と範囲は共有 |
| タブを閉じる | 左右いずれかの隣接タブへ移動。最後のタブを閉じると空画面 |
| アプリを閉じる | タブ順・選択タブ・位置・設定を保存。編集保存の確認は不要 |
| 再起動 | 既定で前回のタブを復元。選択タブだけ本文を読み、他は選んだときに読む |
| 復元を無効にする | 設定で無効化し、次回は空画面。履歴を消す操作も設ける |
| ファイルがない | ほかの復元を継続し、そのタブに「ファイルが見つかりません」と再選択／閉じるを表示 |
| 同名ファイル | タブは名前、ツールチップ・文書情報では場所を確認できる |
| 復元情報の破損 | 破損データを保全し、空画面から開始。起動不能にしない |

タブごとにDocumentId、History、ReadingAnchor、更新状態を持つ。画面用WebViewは一つとする。
タブごとのWebView、全文の常駐、全タブのファイル監視は作らない。
前面文書だけをOSイベントで監視し、背景タブは選択時に変更を確認する。

位置は内容の指紋、見出し階層、段落の指紋・出現順、段落内位置を使う。本文の抜粋は保存しない。
同一内容は同じ段落へ、変更時は一致する段落→近い見出し→先頭へ復帰し、特定できなければ簡潔に知らせる。
復元や背景タブの再読込では最新原稿を使う。表示中の本文は外部保存後に自動更新する。選択・IME変換中は反映を待ち、フォーカスを奪わない。
タブ切替時に本文の選択範囲そのものを完全復元することは初期の保証範囲に含めない。

表示中の版と画像はメモリ上限内で保持する。タブ切替／履歴で再利用できる版があればそれを使う。
破棄済みなら最新原稿を読むことを表示し、利用者が「現在の内容を開く」を選んでから表示する。
アプリ再起動時には古い本文の再現を約束しない。
連続保存を200msの静穏待ち（最大1秒）でまとめ、読込失敗時は80/160/320msの待ちを挟んで再試行する。
前面文書だけを非再帰のOS通知で監視し、タブ選択・アプリへの復帰時に再確認する。監視の再試行は⌘R／Ctrl+Rで行う。
更新中の復帰には段落テキストを一時メモリで扱う。再起動用には段落と見出しの指紋・出現順・読書領域内の相対位置を保存し、本文テキストは保存しない。
一致しない場合は残っている見出し、または元のスクロール位置へ戻し、その旨を通知する。

古い非同期読込結果を世代番号で無効化する。読込中・更新失敗でも最後の正常な本文を保持する。
削除・置換保存は親ディレクトリのイベントも考慮し、手動更新を必ず残す。
保存は変更時のまとめ書きと正常終了時に行い、途中失敗で前回の正常な復元情報を壊さない。
最近の文書は最大20件。タブは上限20件から開始し、上限時は追加分を黙って捨てず、閉じる操作を案内する。
本文・画像キャッシュの合計上限はV1で代表入力と実測を基に固定する。

復元情報はアプリ専用領域のsession.jsonへ形式版1として保存する。表示設定のlocalStorageとは分ける。
スクロール停止後250msにまとめて保存し、タブ切替・閉じる操作・正常終了時にも保存する。
終了時はUIから最後の読書位置の保存完了を待つ。失敗時は前回の情報を保持し、「保存せず終了」を選べる。
破損・未対応形式は別ファイルへ保全して空画面で開始する。1MiBを超える復元情報は読み込み・上書きを止める。
文書名・タブ・メニューの帯は上部へ固定し、タブ切替のために本文の先頭へ戻る必要をなくす。
読書位置の指紋は識別用FNV-1a 64bitで、セキュリティ検証用のハッシュではない。

## 5. Markdownとファイルの境界

UTF-8とUTF-8 BOMの `.md`・`.markdown` を対象にする。CommonMarkに表・取り消し線・チェックリスト・脚注を加える。
先頭のYAML front matterは本文と分けて折りたたみ、原文を確認できるようにする。
PNG・JPEG・WebPを表示し、未対応画像、欠落、読込失敗には理由とaltテキストを表示する。
Mermaid・数式・埋込みHTMLは原文として読めるようにする。文書内スクリプト、実行コード、外部埋込みは動かさない。
lint違反でも閲覧を止めない。整形のために利用者の原稿を変更しない。

読込範囲は利用者が開いたファイルと、その親フォルダー内の相対参照から始める。
親の外への参照は、対象と理由を示して参照フォルダーを選ぶ。文書単位で記憶し、往復時に毎回選び直させない。
UNC・ネットワーク共有は初期版の対象外とし、文書から暗黙にアクセスしない。Windowsのドライブ・大文字小文字・日本語・空白を検証する。
Rustで正規化、シンボリックリンク／再解析ポイント、URLエンコード、実際の読込先を検査する。
WebViewから渡る任意パスを信頼せず、許可済み資産IDだけで画像を渡す。
外部画像・フォントの自動取得は行わない。http/httpsリンクは押すと接続先とURLを確認し、
利用者が「ブラウザで開く」を選んだ場合だけ標準ブラウザへ渡す。キャンセルを初期フォーカスにする。
リンクの表示名を信用の根拠にせず、実際に渡す正規化済みURL全体とASCIIホスト名を表示する。

Rustのexternal.rsで許可するのは明示的なHTTP／HTTPSの絶対URLだけ。8KiBを上限とする。
ユーザー名・パスワード、空の接続先、逆スラッシュ、不正なパーセント表記、制御・方向制御・不可視文字は拒否する。
パーセント復号もUTF-8として検査する。HTTPの暗号化なしを通知する。安全なサイトだと表示する機能は作らない。

確認準備はKnownの開いた原稿を確認してから行い、正規化済みURLをRust側のメモリに一件だけ保持する。
120秒で失効する単回の確認IDを返し、ブラウザ起動コマンドはURLではなくこのIDだけを受け取る。
キャンセル・別の確認・原稿の切替や更新で古い確認を無効にする。確認後にUIの別URLを起動する経路は作らない。
確認IDはUIの確認状態を対応付ける識別子であり、ネットワークの認証トークンではない。

起動はopen 5.3.3（MIT）に委ねる。Windowsはshellexecute-on-windows機能のthat_detachedを用い、cmd /c startを通さない。
macOSはopen::thatからOSの既定URLハンドラーへ渡す。OS起動処理はバックグラウンド実行し、失敗は画面に示す。
自動のGET／HEAD／DNS・リンクプレビュー・レピュテーション照会は実装しない。URLやクエリをログ・セッションへ保存しない。
ブラウザ起動後のリダイレクトやブラウザ側の通信・履歴はこの確認の対象外とする。

原稿・元画像は書き換えない。専用領域へ保存するのは設定、パス、位置、タブ順、形式の版と内容の指紋。
本文・全文索引・アクセス解析は永続化しない。設定・履歴にファイルの場所が残ることを説明する。
本文バイト数、画像バイト数・画素数、合計キャッシュ量に上限を置く。具体値はV1で定める。
読込権限を独自Rustコマンドでも検査し、Tauri capabilitiesとCSPだけに依存しない。

## 6. WindowsとmacOSの導入

| 項目 | Windows | macOS |
| --- | --- | --- |
| 最初の検証対象 | Windows 11 x64 | 手元のApple Silicon Mac |
| 配布予定 | NSISの日本語セットアップ `.exe` | `.app` を入れた `.dmg` |
| 利用者の開発環境 | 不要 | 不要 |
| 文書を開く入口 | ExplorerのOpen With、選択、ドロップ、既定設定後のダブルクリック | FinderのOpen With、選択、ドロップ、既定設定後のダブルクリック |
| レンダラー | OSのWebView2 | OSのWKWebView |
| 署名 | Windows署名の方式・証明書は未決定 | Developer ID署名・公証の実施は未承認 |

`.exe` は初期版ではセットアップ用で、単一のポータブル実行ファイルを意味しない。
WebView2は既存のEvergreen Runtimeを使い、未導入なら組込みbootstrapperで取得する方針。
その場合の初回導入はネット接続が必要。閲覧時のオフライン動作と区別する。
オフラインRuntime同梱はサイズが増えるため初期の標準配布には含めない。
利用者単位の導入を基本にし、必要な権限・企業端末での制約はWindows実機で確認する。
既定のアプリは強制変更せず、OSの選択画面から設定する方法を日本語で案内する。

OSから受け取る引数はファイル名として扱い、shellへ渡さない。起動時引数・稼働中の追加Openイベント・ドロップを同じ経路に統一する。
Windowsはsingle-instance連携、macOSはOpenイベントを含め、既存ウィンドウの新規タブへ配送する。
起動直後の受信をキューに入れ、UI準備前のファイルを失わない。明示的に開いたファイルを復元タブより優先する。

Windows向けはWindows上でビルド・導入・起動・関連付け・アンインストールまで検証する。
macOSのビルド成功やブラウザ上の確認で、Windows対応済みとはしない。
署名されていない試作を、そのまま非エンジニア向けの一般配布完了とは扱わない。
署名購入・公開・GitHub Actionsによる実行は、それぞれ具体的な承認範囲で行う。

## 7. 構成と軽量性

Rustの単一アプリcrate、Tauri 2、同梱HTML/CSS/JavaScriptを使う。利用者にNode.jsは要求しない。
React、DB、ローカルHTTPサーバー、バックグラウンドAI、常駐トレイは初期に追加しない。
Markdownの解析と安全な描画はRustに集約し、UIで再解析しない。解析候補はpulldown-cmark。
Rust UIのみの方式より、文字選択・表・リンク・読み上げに既存WebViewの仕組みを使うことを優先する。
依存の版・ライセンス・脆弱性・OS適合は実装時に確認してlockfileへ固定する。

```text
md-viewer（GitHub上の名前）/
├── README.md
├── README.lab.md                    # 旧README原文
├── docs/markdown-reader/
│   ├── PLAN.md                      # 本書
│   └── TASKS.md                     # 実装順序と完了条件
├── reader/                          # 今後作る独立Cargo package md-viewer
│   ├── Cargo.toml / Cargo.lock
│   ├── tauri.conf.json / build.rs
│   ├── capabilities/reader.json
│   ├── src/
│   │   ├── main.rs / lib.rs          # OSからのopen・限定コマンド
│   │   ├── document.rs               # 読込・解析・資産
│   │   ├── session.rs                # タブ・履歴・復元
│   │   ├── navigation.rs             # リンク・位置
│   │   └── watch.rs                  # 前面文書の更新検知
│   ├── ui/index.html / reader.css / reader.js
│   └── tests/
└── 既存Cargo・src・fixtures・assets・out # 旧ラボを保全
```

背景タブはメタデータ中心にし、本文・DOMは必要なときに生成する。
非表示時の継続アニメーション、定期ポーリング、全文走査、定期的な自動保存タイマーを設けない。
スクロール位置の通知・保存はまとめ、未変更状態の書込みを避ける。

| 測るもの | 方法と記録 |
| --- | --- |
| 起動と文書表示 | OS、CPU、メモリ、ビルド版、文書サイズ、コールド／ウォームを揃え、起動から本文表示までを記録 |
| メモリ | 本体とWebViewの全プロセスを合計。空画面、1文書、10タブ、タブ閉鎖後を比較 |
| 待機負荷 | 読込完了後の前面・背景・最小化でCPU、wakeups、書込み、通信を記録 |
| 更新負荷 | 連続保存時の解析回数、UI停止、処理終了後に待機へ戻るかを確認 |
| エネルギー | macOSのEnergy Impact／利用可能な電力測定、Windowsの利用可能な消費電力指標を環境ごとに記録 |

OS間で異なる指標を直接比較しない。消費電力を計れなければ、CPU等の代替指標と明記する。
根拠なしのMB・ms・Wの合格値は設定しない。V1の実測を基準として、V2で回帰と増加理由を確認する。
「軽量・省エネルギー」を達成済みとするのは、測定と通常利用で裏付けられてからとする。

## 8. 読みやすさと利用者確認

非エンジニアに、説明を先に与えず「受け取った文書を開く」「文字を大きくする」「別の文書を開いて戻る」「再開する」を試してもらう。
操作完了、助けが必要だった箇所、迷い、表示崩れ、位置の探し直しを記録する。閲覧時間の短さだけを成功にしない。
既存アプリとの比較は、相手が普段使う手段を基準とする。VS CodeやArtoの操作知識を前提にしない。
作り手本人の試用、第三者の利用、継続利用、購入意思は別に確認する。

リンク先が見つからない場合は小さく「リンク切れです」と表示し、元の本文と位置を保持する。
上位階層や周辺ディレクトリの再帰探索、似たファイルの推測、自動的な代替リンクへの移動は行わない。

## 9. 名称変更と今回の境界

製品名・GitHubリポジトリ名はmd-viewer。新アプリのCargo packageもmd-viewerとする。
ルートCargo packageは旧ラボなので変更しない。未コミットのコード・検証記録・配布物をそのまま保全する。
ローカルフォルダーはmd-viewerへ変更し、既存参照を保つため旧veil-boundary-labパスには互換シンボリックリンクを残す。
Codexの保存プロジェクト表示名の変更は、操作ツールの制限で未完了。設定ファイルの直接書換えで迂回しない。
GitHubの名前とoriginは変更し、ソースのpush・公開リリース・外部送付は行わない。
