# Windows 0.1.0候補の確認範囲

記録日：2026-10-31。公開対象はWindows x64の未署名候補と対応ソース。コード署名の購入・署名タグのpush・リリース公開は別の判断とする。

## 実機とCI

所有者がHPのWindows 11 Pro本体で、今回のインストーラーから導入・起動できたことを明示した。
この確認は2026-10-30作成の旧候補に対するもので、権利表示を追加して再梱包した候補のハッシュや導入結果と同一には扱わない。
旧候補のSHA-256は3e67f59e03b92c01f015274b6dc5bfd20501f1b50a03da19a7acdce998786b26。

CI成功済みの基準コードは9f2ecab93c70d89a841036651941a0d51978eaa3。
Windows・macOSの整形、Clippy、Rust試験、UI回帰、releaseビルドとWindowsのNSIS作成を確認した。
権利表示・文書の修正後は、その最終コミットのCIと候補を改めて照合する。最新の実行結果は[Check](https://github.com/mt4110/md-viewer/actions/workflows/check.yml)と[Package](https://github.com/mt4110/md-viewer/actions/workflows/package-candidate.yml)で対象SHAを確認する。

## Sandboxの結果と制約

ホストのSACは強制適用、SandboxのSACは標準の評価モードのまま検証した。
日本語の通常セットアップは成功したが、初回起動はWebView2 Runtimeの検出エラーで失敗した。
ゲストでは登録バージョン156.0.4314.50と実ファイル156.0.4314.56が不一致だった。公式修復のログには一時フォルダー作成のアクセス拒否が残った。

Microsoft署名を確認した実体の場所を、起動プロセスにだけ指定すると画面が表示された。
Windows標準のファイル選択、日本語本文・表・チェックリスト・コード・ローカルPNG、文書内検索、Enterでの一致移動、Escでの終了、目次ジャンプと戻るを観察した。操作後も合成文書のハッシュは不変だった。
これは通常のショートカット起動成功とは区別する。HP本体での所有者確認を否定する結果でも、全Windows共通の不具合を証明する結果でもない。

## 権利表示と成果物

固定したWindows向け依存（ビルド用も含む）のライセンス本文・帰属表示・対応ソースURLとハッシュを収録する。
crateに本文がない場合は、パッケージのVCSリビジョンと照合した公開元の原文をtools/licensesへ保持し、ハッシュ不一致・未解決・生成物のずれを検査で拒否する。
静的リンクされるMicrosoft WebView2ローダーは、SDK 1.0.3800.47の配布パッケージと同じバイト列であることを確認し、SDKのLICENSEとNOTICEも収録した。
TauriのNSISヘルパーのMIT表示も含む。製品MITと第三者表示をインストール先から読める形で同梱する。

新しいインストーラーには新しいSHA-256を記録し、ソース・ライセンス表示・最終コミットと対応付ける。
新たな候補の導入・実行確認は、その結果を取得した時点で別途記録する。旧候補の成功を流用しない。

## 未確認の受入項目

HP本体での日本語IME、読み上げ、全キーボード操作、ドラッグ＆ドロップ、OS関連付け、外部リンクの確認・キャンセル、保存追従、複数タブの復元、更新・アンインストールの全項目は未確認。
UI回帰試験のIPC差し替えは、これらのOS統合の成功を意味しない。
Git署名タグとWindows Authenticodeは別であり、SACやSmartScreenの許可を保証しない。保護を無効化することをアプリ利用の前提にはしない。
