# md-viewer

**Markdownの表示方法を知らなくても、受け取った文書を開いて読める、ローカルのMarkdownビューアー。**

AIが作った説明書、仕事で受け取った手順書、調査メモなどの `.md` ファイルを、見出し・表・画像のある文書として表示するアプリです。
対象は、エディタの設定やブラウザ拡張の導入をせずに文書を読みたい人です。

**v0.1.0は開発者向けのソース版です。[Release](https://github.com/mt4110/md-viewer/releases/tag/v0.1.0)のソースアーカイブから取得できます。利用者向けインストーラーは含みません。**
Windows・macOSのCIでRust・UI回帰・releaseビルドを確認しています。macOSの本文表示・目次・検索・文字サイズ・基本タブはローカル試作で確認しました。
WindowsのIME・読み上げ・関連付け・更新・アンインストール等の全受入確認は未完了です。確認範囲は[Windowsの検証記録](docs/markdown-reader/VALIDATION_WINDOWS_0_1_0.md)を参照してください。
所有者はHPのWindows 11 Pro本体で旧インストーラーの導入・起動を確認しましたが、権利表示を追加して再梱包した新候補はSACに開始前に拒否されました。
未署名のEXEとMSIX試作はv0.1.0のReleaseに添付しません。Gitの署名タグはWindowsアプリのコード署名とは別で、SACやSmartScreenでの許可を保証しません。
macOSの配布用アプリのDeveloper ID署名・公証は未完了です。

## こんなときに使う

- AIから保存した文書を開いたら、記号が並んでいて読みづらかった。
- 「このMarkdownを確認してください」と渡されたが、何で開けばよいか分からなかった。
- 説明書をいくつか開いて、タブで切り替えながら読みたい。
- 文書を閉じた後も、読んでいた場所から再開したい。

操作は閉じたメニューへまとめ、本文を広く表示します。検索は⌘F／Ctrl+Fで開き、Escで閉じます。
検索範囲は「この文書」「開いているタブ」で切り替えます。横断結果は文書名と周辺の文章で選べます。
一致箇所へ移動すると一覧を畳み、「検索結果」で再表示できます。Enter／Shift+Enter、前／次でも移動します。
結果は先頭200件まで表示し、上限到達時は検索語を絞る案内を出します。
目次・文書内リンク・検索結果へ移動した後は、メニューの「戻る／進む」で元の読書位置へ戻れます。
ショートカットはmacOSで⌘[／⌘]、WindowsでAlt+←／→です（Windows実機では未検証）。
履歴はタブごとに持ち、タブ切替ではそれぞれの位置を保ちます。履歴自体は再起動後に引き継ぎません。
画面とメニューは日本語が既定です。表示設定からEnglishへ切り替えられます。文書本文は翻訳しません。

Markdownの書き方を覚える必要はありません。アカウントや文書のアップロードも不要にする設計です。

## 開いて、読む

今後の利用者向け配布では、次の使い方を提供する予定です。v0.1.0は下記「試作の起動」の開発者向けビルドが必要です。

1. Windowsではセットアップ用 `.exe`、macOSでは `.dmg` から導入する。
2. ファイルをアプリへドロップするか、「ファイルを開く」で選ぶ。
3. 本文を読み、必要に応じて文字を大きくしたり、目次や検索で探したりする。

「プログラムから開く」「このアプリケーションで開く」からも使えるようにします。
既定のアプリに設定した場合は、文書のダブルクリックで開けます。既定設定は利用者がOS上で選びます。
利用者向け配布では、ソースコードの取得、Rust、Node.js、コマンド操作を不要にすることを目指します。

## 読むために備える機能

以下は実装予定の最小構成です。

| したいこと | 機能 |
| --- | --- |
| 読みやすく表示する | 日本語の本文、見出し、リスト、表、コード、リンク、画像を整形して表示 |
| 自分に合わせる | 文字サイズ、本文の幅、文字色・背景色、配色プリセット、初期値への復帰 |
| 必要なところを探す | 目次、文書内／開いているタブの検索、次／前の一致への移動 |
| 複数の文書を読む | タブ、同じファイルを重複して開かない動作、戻る・進む |
| 続きから読む | 開いていたタブと読書位置の復元、最近の文書 |
| 読書を中断されない | 外部の保存を検知して自動更新し、読書位置をできるだけ維持。選択中・入力変換中は反映を待つ |
| 一部を使う | 文字の選択とコピー。元の文書は書き換えない |

lintの警告がある文書も開けます。閲覧の前に修正作業や専門用語の理解を求めません。
`markdownlint` は、このリポジトリの開発文書を検証するために使い、利用者のアプリには同梱しません。

## 軽く、静かに動く

起動の速さ、メモリ、待機時CPUを計測し、低い負荷で使える構成を目指します。
表示する本文は一つとし、背景のタブは必要になったときに読み込みます。
ファイルの定期的な全走査や、待機中のアニメーションは行わない方針です。

「Rust製だから低消費電力」とは判断しません。WebViewを含むプロセス全体をWindows・macOSで測定します。
現段階で性能・消費電力の測定結果はありません。

## 文書を大切に扱う

元のMarkdownと画像は変更しません。読書位置・タブ・表示設定を、アプリの専用領域に保存する設計です。
復元は設定で無効にできます。本文の永続コピーや全文検索用データベースは作りません。

外部画像・外部フォントは自動取得しません。取得しない画像は理由を表示します。
外部のWebリンクは、押すと接続先ホストとURL全体を確認する画面を表示します。
「ブラウザで開く」を選んだ場合だけ標準ブラウザへ渡します。キャンセル・Escでは接続しません。
HTTP／HTTPSだけを許可し、認証情報付きURLや制御文字などを含むURLは開きません。
国際化ドメインはASCII表記（Punycode）で表示し、HTTPでは暗号化されないことを案内します。
リンク先のプレビュー、DNS・安全性チェックのための自動アクセスはしません。この確認は危険サイトや転送先の安全を保証するものではありません。
開いた後の通信・Cookie・履歴は標準ブラウザの設定に従います。
文書中のスクリプトや実行コードは動かしません。

## 初期版の対応範囲

UTF-8の `.md`・`.markdown`、基本的なMarkdown、表、チェックリスト、脚注に対応する予定です。
ローカル画像はPNG・JPEG・WebPから始めます。
親フォルダー外の画像・関連文書を参照するときは、参照先を選ぶ操作が必要な場合があります。
一度選んだ範囲は記憶し、通常の往復で毎回選び直させない設計です。

編集、AI要約・チャット、PDF・Word出力、クラウド同期、注釈、プラグインは初期版には含めません。
Mermaid・数式・埋込みHTMLは、初期版では元の記法を表示します。完全なGitHub表示互換は約束しません。

## ほかのアプリとの違い

VS Codeやブラウザ拡張を設定することに慣れていない人に、文書を開くための単独アプリを提供します。
既存アプリでも読めている人に、乗り換えを求めるものではありません。
専用のビューアーも既にあるため、独自機能の数より、導入から読書の再開まで迷わず使えるかを確認します。

Markdownを普段扱わない人が、開く・文字を大きくする・別の文書へ切り替える・続きから読む操作を、説明なしで行えるかを試します。
利用者による確認は未実施です。

## 試作の起動（開発者向け）

リポジトリのルートから `rustup run 1.95.0 cargo run --manifest-path reader/Cargo.toml --locked -- README.md` で起動します。
初回ビルドにはRust・各OSのビルド環境とネット接続が必要です。利用者向けの配布手順ではありません。
ローカルMarkdownへのリンクは別タブで開き、見つからない場合は「リンク切れです」と小さく表示します。
再起動時は、開いていたタブと選択タブ・読書位置を復元します。表示設定で復元を無効にできます。
外部WebリンクはURL確認後に標準ブラウザで開きます。参照フォルダー選択はまだ未実装です。
VS Codeなどの外部保存を自動検知します。Vimの置換保存でも動作を確認しました。監視の再試行は⌘R／Ctrl+Rで行えます。
[自動更新の検証結果](docs/markdown-reader/VALIDATION_AUTORELOAD.md)を参照してください。

## 開発について

Rust + Tauri 2 + OSのWebViewを採用する設計です。表示は同梱HTML・CSSと少量のJavaScriptで構成します。
Windowsは日本語のセットアップ `.exe`、macOSは `.dmg` に入れたアプリを配布する予定です。
Windowsで必要なWebView2が未導入の場合、初回セットアップにはネット接続が必要になる設計です。
インストール後のローカル文書の閲覧はネット接続なしで行えるようにします。

- [最小設計・Windows配布・状態管理・性能の確認方法](docs/markdown-reader/PLAN.md)
- [実装タスクとマイルストーン](docs/markdown-reader/TASKS.md)

開発文書の検証：`npx --yes markdownlint-cli2@0.24.0 --config .markdownlint-cli2.jsonc`
このコマンドは開発者用で、初回はnpmからツールを取得します。

## 所有者向けの配布候補検証

[Package Windows test candidate](.github/workflows/package-candidate.yml)は、feat/md-viewerの対象変更時または手動実行で
未署名の日本語NSISセットアップ、対応ソース、SHA-256を生成して検証します。
成果物のアップロードは既定で無効です。権利表示と共有範囲を確認した後、手動実行のupload_artifactで明示的に選んだ場合だけ7日間保存します。
このCIはタグやGitHub Releaseを作成しません。公開は最終コミット・CI・成果物を照合した後に判断します。
セットアップにはLICENSE.txtとTHIRD_PARTY_NOTICES.txt/jsonを同梱します。固定依存の本文・帰属表示・該当ソースの取得先を収録し、不足や生成物の不一致をCIで拒否します。
[Windows実機での確認手順](docs/markdown-reader/WINDOWS_MANUAL_CHECK.md)で、実施済みと未実施を区別しています。

梱包用CLIは@tauri-apps/cli 2.12.4へ固定しています。macOSはreader/で以下を実行します。
既存の成果物を上書きしないよう、別の作業場所と新しいCARGO_TARGET_DIRを使用してください。

```sh
npx --yes --package @tauri-apps/cli@2.12.4 tauri build --ci --no-sign --bundles app,dmg -- --locked
```

これは配布形式のローカル検証用です。Developer ID署名・公証の完了を意味しません。
